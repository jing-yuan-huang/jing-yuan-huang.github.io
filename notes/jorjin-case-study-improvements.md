# Jorjin case study — 可改進項目

> 建立於 2026-11-10。視角:B2B 產品設計 / design-engineer 面試官(對應 QNAP、Super Micro、Ubiquiti 這類高密度 B2B 主控台的缺,CLAUDE.md 裡 Jorjin 的目標受眾)。
> 來源:對 `jorjin.html` 現況的面試官式評論。每條標了優先序與「為什麼面試官會在意」。

## 一句話定位判斷

這篇最強的證明是「**能把設計一路做到上線,而且做決策會講代價**」。它**不是**「我能設計複雜操作型介面 / 處理不確定系統」的證明——因為成品本質是企業形象官網,不是 console。下面的項目多半是在補這個落差,或把宣告改成證據。

---

## P1 — 直接影響可信度,優先改

- [ ] **「幾秒內看懂」目前是宣告,不是證據。**
  - 問題:Discovery 段的「the majority grasp what the company is within seconds」是整篇的核心 UX 主張,但沒有任何測量撐著。踩到 CLAUDE.md 的規則「不要宣告態度,用事實證明」。
  - 面試官會問:這是測出來的,還是你推論的?
  - 做法(擇一):① 補一個行為面佐證(改版後主線頁的停留/互動、跳出率變化);② 做不出數據就改寫成不宣告的版本(描述「怎麼讓它可能被幾秒看懂」的設計手段,而不是斷言結果)。

- [ ] **成效區三個數字全是 SEO / 可見度指標,缺 UX 成效。**
  - 問題:16.8→4.1、6%→11.5%、8 頁索引,都證明「找得到」,不證明「看得懂、好用」。對產品設計缺,面試官要的是任務成功率、理解度、行為改變。
  - 做法:補至少一個行為/理解面的指標,或明確把現有數字定位成「可見度成效」,再用一句話連到 UX(例如 CTR 上升可部分歸因於標題/描述更清楚地說出公司在做什麼)。

- [ ] **缺互動與資訊密度的展示(對 console 受眾最關鍵)。**
  - 問題:「三條產品線、一個故事」的解法只用一張 IA 前後圖帶過。真正像「介面」的東西——導覽結構、一個訪客實際怎麼走、選單/篩選/產品列表怎麼讓三條線不互相淹沒——幾乎沒出現。投 console 缺的人,面試官腦中會拿這個官網去對照一個有表格/批次操作/系統狀態的操作台。
  - 做法:加一小段「導覽 / 資訊密度決策」:怎麼安排主線與次線的層級、如何在不 overwhelm 首訪者的前提下讓三條線都可達。哪怕一張導覽結構圖 + 兩句決策,就能把「這是介面設計」講出來。

## P2 — 補一句就能擋掉質疑

- [ ] **20 元件類型 / 48 版面變體 vs. 約 8 頁的站——補取捨說明。**
  - 問題:對一個不大的站做到這個系統化程度,面試官會想「是剛好,還是 over-engineering?」
  - 做法:加一句取捨——為什麼這個規模的系統化是划算的(例如為了讓 +1 視覺設計師的渲染/影片能零調整落位、為了之後擴充產品頁的邊際成本),而不是堆規模感。

- [ ] **IA 重構缺 user-facing 驗證。**
  - 問題:Discovery 全是內部 stakeholder 訪談;「ODM 當中軸」是合理商業判斷,但沒有 tree test / card sort / 可用性測試佐證。對照 humanfactors、J9 有真的 n= 測試,這篇驗證環最薄。
  - 做法:① 若有做過任何輕量驗證就補上;② 沒有的話,誠實把它定位成「在沒有測試預算下的商業判斷 + 事後用 GSC 行為數據回修」,把 honesty 變成加分而不是漏洞。

## P3 — 風格與定位,斟酌

- [ ] **收尾的「對抗 AI 模板化、堅持 design-first」是 POV,偏 manifesto。**
  - 問題:同樣踩到「不要宣告態度」。有人吃這套,有人覺得沒憑據。
  - 做法:留著就要準備被問「這是信念還是有數據」;或軟化成一句更收斂的觀察。

- [ ] **決定這篇在 portfolio 的角色。**
  - 這篇適合當「end-to-end 落地 + 有代價的決策」那一篇,不適合當「複雜應用 UX / 不確定系統」的主打。
  - 對 Zebra(humanfactors)、Garmin/Logitech(J9)那兩條線,它都不是主角;它是 B2B 官網這條線的料。排版/首頁露出時據此安排。

---

## 備查:這篇目前做得好、不要動的部分

- ODM 當中軸的決策,**有明確寫出取捨**(多兩個受眾一次點擊 ↔ 多數人幾秒看懂)——全篇最強,保留。
- 成效數字有分母、有期間、有出處(GSC),不灌水——可信度的基礎,保留寫法。
- 設計 + Next.js 一手包的 end-to-end 敘事,對小團隊 / design-engineer 缺是加分,保留。
- 影片取代靜態規格圖後,20/48 的宣稱有實體證據撐著——保留。
