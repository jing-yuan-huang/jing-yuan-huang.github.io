## Overview — Design Context

HJ1 是 Jorjin 自主開發的 AI 智慧眼鏡，搭載眼動追蹤模組。在我加入前，公司的展示方式是「眼鏡插手機」，以手機軟體為主，展示眼鏡的螢幕解析度——而非眼鏡本身的互動能力。

加入後，主導設計 HJ1 一體機的完整展示體驗（Demo Experience），讓重要 B2B 客戶能在短時間內真實感受眼動追蹤互動。由於 HJ1 當時尚無完整作業系統，UI 設計需直接提供素材與詳細互動規格給韌體工程師實作，並與其共同測試、調整 UX 參數（包含眼動觸發時程、觸發範圍、數據平滑處理與異端值剔除）。

**主要挑戰：**
- **硬體限制：** 眼動偵測成功率取決於使用者臉部條件（眼距、鼻樑高度、鼻墊尺寸），並非每位客戶都能順利完成校正
- **時間限制：** 展示對象為高層商業客戶，舊版 demo 約 5 分鐘且互動形式不一致（touchpad 與眼動混用），注意力難以維持
- **無 OS 支援：** 設計需完全依賴韌體實作，設計溝通必須足夠精確

---

## Overview — What I Did（條列）

- 設計 HJ1 完整展示體驗（Demo Story Flow），將時長從 5 分鐘壓縮至 1.5 分鐘
- 規劃自動串接機制：每個功能完成後自動推進下一段，偵測失敗時同樣能繼續展示，不中斷流程
- 統一互動模態，全程以眼動追蹤為核心，移除 touchpad / 眼動混用的不一致體驗
- 提供詳細 UI 規格與互動素材，與韌體工程師共同測試調整眼動 UX 參數
- 依不同展示場域（CES、Amazon、運科中心）調整展示情境內容
- 設計運科中心版本的「眼鏡 → 大螢幕」雙屏互動延伸

## Design — Demo Story Flow

**舊版問題：** 約 5 分鐘，touchpad 與眼動控制混用，互動形式不一致，客戶難以聚焦在眼動追蹤的核心優勢。

**新版設計目標：** 1.5 分鐘內，讓客戶完整體驗眼動追蹤從校正到實際應用的全流程，並在偵測條件不理想時仍能走完所有段落。

**展示流程（4 個階段）：**

1. **確認畫面** — 確認使用者能清楚看到眼鏡顯示畫面，建立基本信任感
2. **眼動校正** — 完成 calibration，確立偵測基準點
3. **觸發測試** — 讓使用者體驗眼動選擇的操作感，建立互動信心
4. **使用情境展示** — 示範真實應用場景：會議中收到訊息通知 → 眼動觸發 → 閱讀完整訊息

**關鍵設計決策：** 每個階段完成後自動推進；若眼動偵測未能成功觸發，系統自動播放該段並繼續下一段——確保每位客戶都能體驗完整流程，而非因硬體限制卡在某個環節。

## Design — 三個應用場域

同一套互動設計核心，依場域調整展示情境：

### CES 2026（2026/1/6–1/9，Las Vegas）
國際消費電子展，面向國際 B2B 客戶。使用標準展示流程，以會議訊息情境為主。

### Amazon B2B Demo
展示場域為會議室，情境設計貼近辦公環境：會議進行中收到訊息通知出現在智慧眼鏡畫面，使用者透過眼動觸發閱讀完整訊息。讓客戶直觀感受眼動互動在企業情境下的應用價值。

### 運科中心展示
展示情境改為體育運動分析：觀看不同球路軌跡 → 眼動選擇其中一條 → 結果同步呈現於現場大型互動螢幕。此版本額外設計了「眼鏡 → 大螢幕」的雙屏互動延伸，展示眼動追蹤技術在實體空間中的延展能力。

## Design — Error Recovery

眼動偵測因使用者臉部條件差異（眼距、鼻樑高度、鼻墊尺寸）存在成功率不確定性，為此設計以下應對機制：

- **偵測未觸發 → 自動播放並推進：** 每個互動段落設有 timeout，未觸發時系統自動完成該段動作並進入下一段，確保展示流程不中斷
- **校正不理想 → 視覺引導重新對焦：** 提供清楚的視覺提示引導使用者調整注視位置，降低校正失敗率
- **整體設計原則：** 讓「失敗」對觀看者不可見——即使眼動偵測未能完美觸發，展示仍能繼續進行
